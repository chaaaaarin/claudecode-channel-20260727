# 🎁 独立検証の見方チェックリスト（自分でベンチマークを疑う）

公式発表の「圧勝」表現をそのまま信じず、自分で確かめるための判断シートです。

**受け取り方**: 下のコードブロック右上のコピーボタンでコピーするか、このファイルをそのままダウンロードしてください。

**使い方**: 新モデルの「〇〇が最強」という発表を見るたびに、このシートを上から順にチェックしてください。

```text
【独立検証の見方チェックリスト】

■ ステップ1：発表元を確認する
□ そのベンチマーク結果は、モデルを開発した企業自身が公表したものか？
→ YES: 自社に有利な条件・ハーネスを選んでいる可能性を割り引いて読む
□ 独立した第三者機関（Epoch AI・Artificial Analysis等）の評価は見つかるか？
→ YES: 両方を並べて、結論が一致しているか確認する
指示例: 〇〇の公式ベンチマークについて、独立した第三者機関の評価も探して両方教えて

■ ステップ2：数字の中身を見る
□ パーセンテージや点数の「差」は、実務で体感できるほど大きいか？
→ YES: 数ポイント程度の差なら「僅差」として扱う
□ 比較対象の設定（effort・ハーネス・試行回数）は同条件か？
→ YES: 条件が違うなら単純比較できないと明記する
指示例: このベンチマーク比較、比較条件（設定・試行回数）が揃っているか確認して

■ ステップ3：自分のタスクで再現する
□ 自分が実際によく頼む作業を3つ書き出せているか？
→ YES: その3つを両方のモデルに同じ条件で投げて比較する
□ 一度きりの結果で判断せず、複数回試したか？
→ YES: ブレが大きい場合は「相性の良し悪し」として記録する
指示例: 普段よく頼む作業を3つ挙げるので、それぞれ2つのモデルで実行して結果を比較して

■ ステップ4：レビュー・口コミを鵜呑みにしない
□ そのレビューは実名・検証可能なアカウントによるものか？
→ YES: 匿名の断片的な感想より重みを置いて良い
□ レビューが「勝った/負けた」の二択で語られていないか？
→ YES: どの用途で勝ち、どの用途で負けたかを分けて読む
指示例: このレビューの主張を、良い点と悪い点に分けて整理して

■ ステップ5：判断を保留する勇気を持つ
□ 情報が出そろっていない段階（発表直後1週間以内）ではないか？
→ YES: 数週間待って複数の実測が出そろってから本格導入を判断する
□ 「今すぐ乗り換えるべきか」の結論を急いでいないか？
→ YES: 小さいタスクで試してから段階的に移行する
指示例: 発表からまだ日が浅いモデルなので、いきなり全面移行せず一部タスクだけで試したい。試すのに向いているタスクを教えて
```

**ポイント**: 「公式が勝ったと言っている」＝「あなたの作業でも勝つ」ではありません。自分のタスクで試すステップだけは省略しないでください。
